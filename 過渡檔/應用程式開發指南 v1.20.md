### **第二章：核心理念與技術棧**

#### **2.1 核心理念**

* **模組化與職責分離**: 應用程式採用嚴格的四層架構，將狀態管理、核心計算、高層分析與使用者介面徹底解耦，確保了程式碼的高內聚、低耦合，便於獨立測試、維護與未來擴展。
* **引導式計算**: 程式應作為設計夥伴，能理解參數間的依賴關係，在資料不完整時引導使用者補全，並自動推算可衍生的參數。
* **設計驗證**: 內建驗證機制，主動檢查幾何矛盾與物理極限，確保設計的嚴謹性與安全性。
* **視覺化回饋**: 提供即時的 3D 視覺化回饋，讓設計過程更直觀。
* **中央化設定**: 將所有可調整的預設值、樣式、演算法參數、乃至 UI 選項文字與佈局比例，全面集中到單一的設定檔 (`config.py`) 中，實現了設定與程式碼的徹底分離，便於快速微調與維護。
* **使用者狀態追蹤**：應用程式應能追蹤使用者的修改狀態，並在關閉前主動提示儲存未保存的變更，確保工作不會意外遺失。

#### **2.2 建議技術棧**

* **程式語言**: Python 3.x
* **數值/科學計算**: NumPy, SciPy
* **GUI 框架**: PyQt6
* **3D 視覺化**: PyVista / PyVistaQT
* **資料庫**: SQLite
* **報告生成**: ReportLab

### **第三章：變數與參數定義**

本章定義了應用程式中使用的所有關鍵變數，作為唯一的參考標準。

* **GUI 與核心引擎單位約定**:
    * **GUI 層**: 長度單位為 **毫米 (mm)**。
    * **核心引擎層**: 長度單位為 **米 (m)**。
    * **資料流**: GUI 層負責在傳遞參數前後進行單位換算。
    * **加速度單位**: GUI 層使用**重力加速度 (g)**，核心引擎層使用 `m/s²`。
* **幾何參數**:
    * $R_a$ (m): **固定平台**節點圓的半徑。
    * $R_b$ (m): **活動平台**節點圓的半徑。
    * $H$ (m): **自然平衡零位高度**。
    * $h$ (m): **平台初始高度**。
    * **自然零位偏移** $(T_{x0}, T_{y0})$ (m): 與 $H$ 同時解算出的水平偏移。
    * **六自由度平台**: $D_f, d_f, D_m, d_m$ (m)。
    * **相位角** $\Delta\theta$ (rad 或 deg)。
    * **三自由度平台**: $D_1, D_2, d_1, d_2$ (m)。
* **電動缸參數**:
    * $L$ (m): 最小機械長度。
    * $s$ (m): 最大可用行程。
    * $s_{buffer}$ (m): 安全緩衝區。
* **動力學參數**:
    * $m$ (kg): 總質量。
    * $I$ (kg·m²): 轉動慣量張量。
    * $a$ (m/s²): 線性加速度。
    * $\alpha$ (rad/s²): 角加速度。
* **姿態參數**:
    * $T = (T_x, T_y, T_z)$ (m): 平移位移。
    * $R = (\phi, \theta, \psi)$ (rad 或 deg): 旋轉歐拉角 (Roll, Pitch, Yaw)。
* **計算結果**:
    * $L_i$ (m): 各電動缸的即時長度。
    * $F_i$ (N): 各電動缸的即時出力。
    * $F_{max}$ (N): 全域最大出力。

### **第四章：數學模型與演算法**

#### **4.1 平台標準方位與自由度定義**

[假想示意圖描述：固定平台在底部，活動平台在上部，X 軸指向前方，Y 軸指向右方，Z 軸向上。]

* **平移自由度**:
    * $T_x$ (Surge): 前後平移 (+ 前進)。
    * $T_y$ (Sway): 左右平移 (+ 右移)。
    * $T_z$ (Heave): 上下平移 (+ 上升)。
* **旋轉自由度**:
    * $\phi$ (Roll): 左右傾斜 (+ 右側下壓)。
    * $\theta$ (Pitch): 前後傾斜 (+ 抬頭)。
    * $\psi$ (Yaw): 左右旋轉 (+ 順時針)。

#### **4.2 運動學模型**

* **逆向運動學 (Inverse Kinematics)**: $L_i = || p_i - q_i ||$。
* **工作空間分析**: 使用 SLSQP 最佳化求解邊界。

#### **4.3 動力學模型**

* **逆動力學 (Inverse Dynamics)**: 使用雅可比矩陣 $J$： $\tau = J^T F$。

#### **4.4 全域分析演算法**

* **LHS + SQP 混合策略**: 使用拉丁超立方採樣 (LHS) 生成初始點，然後用序列二次規劃 (SQP) 尋找極值。

### **第五章：應用程式架構與模組設計**

`[開發者註記：本章已根據 v1.20 的架構進行更新。]`

#### **5.1 層次一：狀態管理層 (`state_manager.py`)**

* **角色**: `StateManager` 類別，應用程式**唯一、權威的數據中心**。
* **職責**: 集中管理所有需要跨模組共享或持久化的狀態。

#### **5.2 層次二：核心計算層**

* **1. 運動學核心 (`kinematics.py`)**
    * **角色**: `CoreEngine` 類別，專注於**運動學與幾何求解**，並作為**所有檔案 I/O 的統一管理者**。
    * **職責**: 封裝數學運算；負責主專案檔 (`.json`) 與**獨立驅動系統設計檔 (`.dsd`)** 的讀寫。

* **2. 動力學核心 (`dynamics_engine.py`)**
    * **角色**: `DynamicsEngine` 類別，專注於**逆動力學計算**。

* **3. 驅動系統核心 (`drive_system_engine.py`)**
    * **角色**: `DriveSystemEngine` 類別，專注於**驅動鏈的工程校核**。
    * **職責**: 實作**雙模式計算邏輯**（手動/自動）。

#### **5.3 層次三：高層分析層 (`analysis_engine.py`)**

* **角色**: `AnalysisEngine` 類別，一個**獨立的、執行緒安全的背景工作者**。
* **職責**: 執行計算密集的分析任務，避免 UI 阻塞。

#### **5.4 層次四：使用者介面與協調層 (GUI)**

* **1. 主視窗 (`main_window.py`)**
    * **角色**: `MainWindow` 類別，**UI 總管**與**事件協調中心**。
    * **職責**: 使用 **`QStackedWidget`** 管理主佈局；協調模式切換；**動態管理檔案選單**；控制事件與資料流。

* **2. 驅動系統儀表板 (`drive_system_widget.py`)**
    * **角色**: 一個獨立的、功能完整的「**驅動系統設計儀表板**」。
    * **職責**: 採用**左右分割佈局**；提供完整的參數輸入介面；在右側面板**即時反饋**計算結果與零件規格；透過訊號與公用函式與 `MainWindow` 進行通訊。

* **3. 其他功能面板 (`controls/` 目錄下的元件)**
    * **角色**: 專用的 UI 元件，負責特定功能的「顯示」與「使用者輸入」。

* **角色**: `ReportGenerator` 類別，一個獨立的報告生成引擎。

#### **5.6 模組六：資料庫管理 (`database_manager.py`)**

* **角色**: `DatabaseManager` 類別，負責管理零件資料庫。

### **第六章：開發者註記與決策記錄**

本章旨在記錄在達成各穩定基線的過程中，所遇到的關鍵挑戰、錯誤分析以及最終的解決方案。

* **[新增] 6.1 迭代修正十一：v1.20 驅動系統模組重構與儀表板開發**
    * **主題**：為從根本上提升「驅動系統計算」功能的獨立性、專業性與易用性，對其前後端進行了一次全面的重構與介面革新。
    * **遇到的問題與決策記錄**：
        1.  **問題回顧**：v1.19 的驅動系統功能僅是一個依附於主模擬流程的簡單校核工具，缺乏獨立設計能力，且介面與後端計算邏輯均採用了過於簡化的模型，導致其計算結果（如扭矩）出現嚴重偏差。
        2.  **核心決策：轉向獨立設計工具**：與專案負責人共同決策，確立了將此模組升級為一個既能整合、又能獨立運作的「雙模式設計工具」的核心目標。
        3.  **架構決策：導入儀表板介面**：為實現「即時因果反饋」的最佳使用者體驗，摒棄了傳統的單欄式佈局，採用了「左側輸入、右側反饋」的儀表板 `QHBoxLayout` 佈局。為此，對 `main_window.py` 的頂層架構進行了重構，引入 `QStackedWidget` 以管理不同模式下的主畫面。
        4.  **功能決策：建立獨立存檔機制**：為配合「手動模式」的獨立設計流程，建立了全新的 `.dsd` 檔案格式與對應的檔案選單，並實現了模式感知的選單動態啟用/禁用邏輯。
    * **最終方案：確立 v1.20 穩定基線**：
        1.  **後端重構**：在 `drive_system_engine.py` 中，完整實作了基於《開發規格書 v1.0》的精確計算模型，並建立了清晰的雙模式（手動/自動）計算分支。
        2.  **前端重構**：在 `drive_system_widget.py` 中，建立了包含所有必要工程參數（如效率值、速度要求）的儀表板 UI，並實現了即時的規格比較高亮與數據總覽功能。
        3.  **Bug 修正與驗證**：透過植入除錯代碼，成功定位並修正了潛藏的扭矩單位換算 Bug，並透過獨立的 `test_drive_system.py` 腳本驗證了重構後引擎的準確性。
    * **[註記：已解決]** 所有上述重構與修正均已在 v1.20 穩定版中完成。
