#### **1.2 虛擬環境建置**

使用虛擬環境可以隔離專案依賴，避免與系統全域套件衝突。

1.  **開啟終端**: 在 VS Code 中，點擊 `Terminal` \> `New Terminal`。
2.  **確認路徑**: 確保終端機的路徑在 `D:\Python_Programs\Stewart_Platform`。
3.  **建立虛擬環境**: 執行 `python -m venv .venv`。
4.  **啟動虛擬環境**: 執行 `.\.venv\Scripts\activate`。
5.  **(可選) 選擇直譯器**: VS Code 可能會自動偵測到虛擬環境。如果沒有，手動點擊右下角的 Python 版本，選擇 `.venv` 中的 Python 直譯器。

#### **1.3 前置套件安装**

1.  在專案根目錄下建立 `requirements.txt` 檔案，並填入以下內容：
    ```text
    numpy
    scipy
    PyQt6
    pybullet
    reportlab
    pyvista
    pyvistaqt
    ```
2.  在已啟動虛擬環境的終端機中，執行 `pip install -r requirements.txt`。

### **第二章：核心理念與技術棧**

#### **2.1 核心理念**

* **模組化與職責分離**: **(v1.7 核心升級)** 應用程式採用嚴格的四層架構，將狀態管理、核心計算、高層分析與使用者介面徹底解耦，確保了程式碼的高內聚、低耦合，便於獨立測試、維護與未來擴展。
* **引導式計算**: 程式應作為設計夥伴，能理解參數間的依賴關係，在資料不完整時引導使用者補全，並自動推算可衍生的參數。
* **設計驗證**: 內建驗證機制，主動檢查幾何矛盾與物理極限，確保設計的嚴謹性與安全性。
* **視覺化回饋**: 提供即時的 3D 視覺化回饋，讓設計過程更直觀。
* **[修改] 中央化設定**: **(v1.11 核心升級)** 將所有可調整的預設值、樣式、演算法參數、乃至 UI 選項文字與佈局比例，**全面集中**到單一的設定檔 (`config.py`) 中，實現了設定與程式碼的徹底分離，便於快速微調與維護。
* **使用者狀態追蹤**：應用程式應能追蹤使用者的修改狀態，並在關閉前主動提示儲存未保存的變更，確保工作不會意外遺失。

#### **2.2 建議技術棧**

* **程式語言**: Python 3.x
* **數值/科學計算**: NumPy, SciPy
* **GUI 框架**: PyQt6
* **3D 視覺化**:
    * **PyVista / PyVistaQT**: (**現行方案**) 基於 VTK 的高階 API，已在本專案中用於在 PyQt 應用程式中嵌入高效能、互動式的 3D 場景，負責平台的幾何結構與姿態顯示。
* **資料庫**: SQLite (用於內建組件資料庫)
* **報告生成**: ReportLab / FPDF (用於匯出PDF報告)

### **第三章：變數與參數定義**

本章定義了應用程式中使用的所有關鍵變數，作為唯一的參考標準。

* **GUI 與核心引擎單位約定**:
    * **GUI 層**: 為了符合使用者習慣，所有在圖形介面 (`GeometryWidget`, `DynamicsWidget`) 的輸入框中，長度單位皆為 **毫米 (mm)**。
    * **核心引擎層 (`CoreEngine`)**: 為了符合科學計算標準，所有內部計算與參數儲存，長度單位皆為 **米 (m)**。
    * **資料流**: GUI 層在將參數傳遞給核心引擎前，負責將 `mm` 轉換為 `m`。核心引擎回傳計算結果時，GUI 層負責將 `m` 轉換回 `mm` 進行顯示。
    * **加速度單位**: GUI 層為了方便使用者輸入，線性加速度單位使用**重力加速度 (g)**。在將參數傳遞給核心引擎前，GUI 層負責將 `g` 值乘以 `9.81` 轉換為核心引擎所使用的 `m/s²` 單位。
* **幾何參數**:
    * $R_a$ (m): **固定平台**節點圓的半徑。
    * $R_b$ (m): **活動平台**節點圓的半徑。
    * $H$ (m): **自然平衡零位高度 (Natural Balance Zero Position Height)**。此為一個**計算結果**，定義為當所有電動缸長度均處於其**可用行程中點** ($L + s_{buffer}/2 + s/2$) 時，平台在保持水平姿態下的高度。它是所有姿態控制和工作空間分析的**操作基準零點**。
    * $h$ (m): **平台初始高度 (Initial Height)**。此為一個理論上的物理量，定義為當所有電動缸長度均處於其**最小機械長度** ($L$) 時，平台在保持水平姿態下的高度。它代表了平台的**物理下限**，對應總機械行程的起點。
    * **自然零位偏移** $(T_{x0}, T_{y0})$ (m): 與 $H$ 同時解算出的，在自然平衡零位下的水平面偏移量。
    * **六自由度平台**:
        * $D_f$ (m): **固定平台**相鄰節點間的較大弦長。
        * $d_f$ (m): **固定平台**相鄰節點間的較小弦長。
        * $D_m$ (m): **活動平台**相鄰節點間的較大弦長。
        * $d_m$ (m): **活動平台**相鄰節點間的較小弦長。
    * **相位角** $\Delta\theta$ (rad 或 deg): **相位角 (Phase Angle)**，亦可稱為 **交錯角 (Stagger Angle)** 或 **扭轉角 (Twist Angle)**。
        * **定義**: 定義為**活動平台**與**固定平台**之間的相對旋轉角。它是六自由度平台結構的關鍵參數，用於決定上、下節點的相對定位。
        * **計算公式**: 相位角 $\Delta\theta$ 可由弦長參數 $D_f, d_f, D_m, d_m$ 推導得出，但為了符合使用者習慣，在 UI 介面中，我們選擇讓使用者直接輸入 $\Delta\theta$，並由程式自動計算出相應的弦長值。
        * **物理意義**: 相位角控制了平台的穩定性與運動範圍。較大的相位角可提升平台的抗傾覆能力，但可能限制其旋轉自由度。
        * **單位**: 在 GUI 中顯示為度數 (deg)，但核心引擎中統一轉換為弧度 (rad) 進行計算。
    * **三自由度平台**:
        * $D$ (m): **固定平台**相鄰節點間的弦長。
        * $d$ (m): **活動平台**相鄰節點間的弦長。
* **電動缸參數**:
    * $L$ (m): 電動缸的最小機械長度 (Minimum Mechanical Length)。
    * $s$ (m): 電動缸的最大可用行程 (Maximum Usable Stroke)。
    * $s_{buffer}$ (m): 電動缸的安全緩衝區 (Safety Buffer)，用於防止電動缸過度伸展或壓縮。
* **動力學參數**:
    * $m$ (kg): 平台的總質量 (包括負載)。
    * $I$ (kg·m²): 平台的轉動慣量張量 (Inertia Tensor)。
    * $a$ (m/s²): 平台的線性加速度向量。
    * $alpha$ (rad/s²): 平台的角加速度向量。
    * $g$ (m/s²): 重力加速度，常數 9.81 m/s²。
* **姿態參數**:
    * $T = (T_x, T_y, T_z)$ (m): 平台的平移位移向量，相對於自然平衡零位。
    * $R = (\phi, \theta, \psi)$ (rad 或 deg): 平台的旋轉歐拉角 (Roll, Pitch, Yaw)。
* **計算結果**:
    * $L_i$ (m): 各電動缸的即時長度。
    * $F_i$ (N): 各電動缸的即時出力 (從逆動力學計算得出)。
    * $F_{max}$ (N): 全域最大出力 (從全域分析得出)。

### **第四章：數學模型與演算法**

`[開發者註記：本章內容自 v1.6 後保持穩定，其數學模型與方位定義是後續所有高層分析功能的基礎。]`

#### **4.1 平台標準方位與自由度定義**

*(v1.6 新增：以下為平台標準方位示意圖，用於統一所有計算與顯示的方向。)*

[假想示意圖描述：固定平台在底部，活動平台在上部，X 軸指向前方，Y 軸指向右方，Z 軸向上。]

* **平移自由度**:
    * $T_x$ (Surge): 前後平移 (+ 前進)。
    * $T_y$ (Sway): 左右平移 (+ 右移)。
    * $T_z$ (Heave): 上下平移 (+ 上升)。
* **旋轉自由度**:
    * $\phi$ (Roll): 左右傾斜 (+ 右側下壓)。
    * $\theta$ (Pitch): 前後傾斜 (+ 抬頭)。
    * $\psi$ (Yaw): 左右旋轉 (+ 順時針)。

#### **4.2 運動學模型**

* **逆向運動學 (Inverse Kinematics)**: 給定平台的姿態 $P = (T, R)$，計算各電動缸的長度 $L_i$。
    公式： $L_i = || p_i - q_i ||$，其中 $p_i$ 為活動平台節點，$q\_i$ 為固定平台節點。
* **工作空間分析**:
    使用 SLSQP 最佳化求解邊界。

#### **4.3 動力學模型**

* **逆動力學 (Inverse Dynamics)**: 給定平台的運動參數，計算各電動缸的出力 $F_i$。
    使用雅可比矩陣 $J$： $\tau = J^T F$，其中 $\tau$ 為扭矩向量。
    *(v1.6 新增註解：轉動慣量張量 $I$ 目前採用固定近似值；v1.11 已將此近似值移至 `config.py` 統一管理。)*

#### **4.4 全域分析演算法**

* **LHS + SQP 混合策略**: 使用拉丁超立方採樣 (LHS) 生成初始點，然後用序列二次規劃 (SQP) 尋找極值。
    *(v1.7 新增：用於全域最大靜載分析；v1.8 升級為雙模式 (靜態/動態)；v1.11 新增節點擺角範圍分析，並將演算法參數移至 `config.py` 統一管理。)*

### **第六章：開發者註記與決策記錄**

本章旨在記錄在達成各穩定基線的過程中，所遇到的關鍵挑戰、錯誤分析以及最終的解決方案。這份記錄是未來維護與功能迭代的寶貴資產，旨在避免重蹈覆轍。

* **[新增] 6.1 迭代修正十：v1.19 UI 架構重構與穩定性總結**
    * **主題**：為從根本上解決自 v1.18 開發分支以來，長期存在的、多種方案均告失敗的頑固 UI 佈局問題，對主視窗的 UI 架構進行了一次決定性的重構。
    * **遇到的問題與決策記錄**：
        1.  **問題回顧**：專案長期被兩個核心佈局問題困擾：1) 主視窗左右 `QSplitter` 面板的比例無法固定；2) 左側面板在內容超出時無法正常、完整地進行垂直或水平滾動，導致 UI 元件被截斷或消失。
        2.  **失敗的嘗試**：在 v1.19 的開發週期中，歷經了多輪失敗的嘗試，包括：微調尺寸策略 (`QSizePolicy`)、移除彈性空間 (`addStretch`)、強制設定元件高度/寬度等。這些「補丁式」的修改不但未能解決問題，反而因引入了過於複雜和相互衝突的佈局規則，導致了更嚴重的**功能衰退 (Regression)**，例如 `QGroupBox` 邊框消失、在其他頁籤中出現新的滾動問題等。
        3.  **根本原因診斷**：最終確認，所有問題的根源在於一個**架構性缺陷**：讓一個**單一的 `QScrollArea`** 去管理一個包含了三個複雜且尺寸動態變化的頁籤 (`QTabWidget`) 的元件。這個「一對多」的滾動管理模式，使得佈局計算變得極其複雜且不可預測。
    * **最終方案：確立 v1.19 穩定基線的全新 UI 架構**：
        1.  **採納「Menu Bar 整合計畫」**：與專案負責人共同決策，採納了一個更優雅且技術上更穩健的方案——**廢除頁籤佈局**。
        2.  **導入功能表列導航**：在 `main_window.py` 中，將原有的三個頁籤，改為直接放置在主功能表列 (`QMenuBar`) 上的三個可選中的模式選項，由 `QActionGroup` 確保其互斥性。
        3.  **實作獨立滾動區**：將原有的 `QTabWidget` 替換為 `QStackedWidget`。在將每一個功能面板（`MasterGeometryWidget`, `DynamicsWidget` 等）加入 `QStackedWidget` **之前**，都為其外層包裹了一個**專屬的 `QScrollArea`**。
        4.  **解決方案優勢**：這個「**每個面板都有自己的滾動區**」的新架構，將複雜的佈局問題分解為三個獨立的、簡單的問題，從而徹底根治了所有滾動與邊框截斷的頑固 Bug。同時，新的 UI 介面更加簡潔、專業，操作路徑也更短。
        5.  **精修與完善**：在新架構穩定後，進一步完成了多項 UI/UX 優化，包括將視角控制工具列整合進選單、統一全域字體、解決因 `QScrollArea` 預設行為導致的元件拉伸問題等。
    * **[註記：已解決]** 所有上述問題已在 v1.19 穩定版中透過 UI 架構重構與精修徹底解決。

* **6.2 迭代修正九：v1.12 新增分析維度與報告功能**
    * **主題**：擴充分析維度，為硬體選型提供數據支持；並實現數據持久化，生成專業的設計報告。

    * **用途**: 這兩個函式庫是實現 3D 視覺化介面的核心。`PyVista` 提供了一套對 `VTK` 的高階封裝，簡化了 3D 物件的創建與操作；`PyVistaQT` 則提供了 `QtInteractor` 元件，讓 PyVista 渲染視窗可以成為獨立視窗並與主程式互動。
    * **資源**: `PyVista` 官方文件 ([https://docs.pyvista.org/](https://docs.pyvista.org/)) 及 PyVistaQT GitHub 儲存庫。

    * **用途**: 未來若要擴展動態模擬、碰撞檢測等功能，PyBullet 將會是首選的物理引擎。
    * **資源**: `PyBullet` 官方指南 ([https://pybullet.org/wordpress/](https://pybullet.org/wordpress/))。
