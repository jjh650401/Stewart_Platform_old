### **第二章：核心理念與技術棧**

#### **2.1 核心理念**

* **模組化與職責分離**: 應用程式採用嚴格的四層架構。
* **引導式計算**: 程式應能理解參數依賴，並自動推算衍生參數。
* **設計驗證**: 內建驗證機制，檢查幾何與物理極限。
* **視覺化回饋**: 提供即時的 3D 視覺化回饋。
* **中央化設定**: 所有可調整參數集中到 `config.py` 管理。
* **使用者狀態追蹤**：在關閉前提示儲存未保存的變更。

#### **2.2 建議技術棧**

* **程式語言**: Python 3.x
* **數值/科學計算**: NumPy, SciPy
* **GUI 框架**: PyQt6
* **3D 視覺化**: PyVista / PyVistaQT
* **資料庫**: SQLite
* **報告生成**: ReportLab

### **第三章：變數與參數定義**

本章定義了應用程式中使用的所有關鍵變數。

* **GUI 與核心引擎單位約定**:
    * **GUI 層**: 長度為 **毫米 (mm)**，加速度為**重力加速度 (g)**。
    * **核心引擎層**: 長度為 **米 (m)**，加速度為 `m/s²`。
* **幾何參數**:
    * $R_a, R_b$ (m): 固定/活動平台半徑。
    * $H$ (m): 自然平衡零位高度。
    * $h$ (m): 平台初始高度。
    * **六自由度平台**: $D_f, d_f, D_m, d_m$ (m)。
    * **相位角** $\Delta\theta$ (rad 或 deg)。
    * **三自由度平台**: $D_1, D_2, d_1, d_2$ (m)。
* **電動缸參數**: $L, s, s_{buffer}$ (m)。
* **動力學參數**: $m, I, a, \alpha$。
* **姿態參數**: $T = (T_x, T_y, T_z)$, $R = (\phi, \theta, \psi)$。
* **計算結果**: $L_i, F_i, F_{max}$。

### **第四章：數學模型與演算法**

#### **4.1 平台標準方位與自由度定義**
* **平移**: $T_x$ (Surge), $T_y$ (Sway), $T_z$ (Heave)。
* **旋轉**: $\phi$ (Roll), $\theta$ (Pitch), $\psi$ (Yaw)。

#### **4.2 運動學模型**
* **逆向運動學**: $L_i = || p_i - q_i ||$。
* **工作空間分析**: 使用 SLSQP 最佳化求解邊界。

#### **4.3 動力學模型**
* **逆動力學**: 使用雅可比矩陣 $J$： $\tau = J^T F$。

#### **4.4 全域分析演算法**
* **LHS + SQP 混合策略**: 拉丁超立方採樣 + 序列二次規劃。

### **第五章：應用程式架構與模組設計**

`[開發者註記：本章已根據 v1.21 的架構進行更新。]`

#### **5.1 層次一：狀態管理層 (`state_manager.py`)**
* **角色**: `StateManager` 類別，應用程式**唯一、權威的數據中心**。

#### **5.2 層次二：核心計算層**
* **1. 運動學核心 (`kinematics.py`)**: 專注於**運動學與幾何求解**，並作為**所有檔案 I/O 的統一管理者**。
* **2. 動力學核心 (`dynamics_engine.py`)**: 專注於**逆動力學計算**。
* **3. 驅動系統核心 (`drive_system_engine.py`)**: 專注於**驅動鏈的工程校核**，實作**雙模式計算邏輯**。

#### **5.3 層次三：高層分析層 (`analysis_engine.py`)**
* **角色**: `AnalysisEngine` 類別，一個**獨立的、執行緒安全的背景工作者**。

#### **5.4 層次四：使用者介面與協調層 (GUI)**
* **1. 主視窗 (`main_window.py`)**: **UI 總管**與**事件協調中心**。使用 **`QStackedWidget`** 管理主佈局；協調模式切換；**動態管理檔案選單**；實現**智慧視窗大小與位置管理**。
* **2. 驅動系統儀表板 (`drive_system_widget.py`)**: 獨立的「**驅動系統設計儀表板**」，採用**左右分割佈局**，實現即時反饋。
* **3. 其他功能面板 (`controls/` 目錄下的元件)**: 專用的 UI 元件。
    * **`geometry_widget.py`**: 一個**無狀態的 UI 工廠**，負責以程式化的方式建立幾何輸入與分析結果的 UI 元件。

#### **5.5 模組五：輸出與報告 (`report_generator.py`)**
* **角色**: `ReportGenerator` 類別，一個獨立的報告生成引擎。

#### **5.6 模組六：資料庫管理 (`database_manager.py`)**
* **角色**: `DatabaseManager` 類別，負責管理零件資料庫。

### **第六章：開發者註記與決策記錄**

* **[新增] 6.1 迭代修正十二：v1.21 佈局最終修正與功能擴充**
    * **主題**：對 UI 佈局進行了根本性的修正，並為驅動系統模組加入了更精確的物理模型與工程校核功能。
    * **遇到的問題與決策記錄**：
        1.  **問題回顧 (佈局)**：歷經多次嘗試後，左側面板的寬度問題依然存在。最終分析確認，問題根源在於「平台計算與分析」區塊中，因混合使用多種類型元件（按鈕、標籤對、內嵌 GroupBox）而導致的 `QFormLayout` 計算混亂。
        2.  **佈局最終方案**：採納了「**拆分區塊**」與「**重構佈局**」的最終方案。在 `geometry_widget.py` 中，將原有的單一 `QGroupBox` 拆分為獨立的「按鈕區」和「結果顯示區」，並為結果顯示區改用 `QGridLayout`，透過新增一個可拉伸的「空白欄」來吸收多餘空間，從而徹底根治了寬度問題。
        3.  **問題回顧 (計算)**：發現 `drive_system_engine.py` 中存在簡化假設，導致「靜止負載」與「平均負載」的計算在物理上不完全準確。
        4.  **計算模型修正方案**：將 `install_angle` 提升為通用參數，並修正了 $F_s$ 與 $F_{eq}$ 的計算公式，確保了模型的普遍適用性與準確性。為此，將《驅動系統計算模-組 - 開發規格書》進版至 `v1.1`。
    * **[註記：已解決]** 所有已知的佈局與計算模型問題，均已在 v1.21 穩定版中修正。

* **6.2 迭代修正十一：v1.20 驅動系統模組重構與儀表板開發**
    * **主題**：為從根本上提升「驅動系統計算」功能的獨立性、專業性與易用性，對其前後端進行了一次全面的重構與介面革新。
    * **最終方案**：確立了雙模式計算邏輯；建立了獨立的 `.dsd` 存檔功能；導入了 `QStackedWidget` 管理的儀表板介面；修正了扭矩計算 Bug。
    * **[註記：已解決]**

* **6.3 迭代修正十：v1.19 UI 架構重構與穩定性總結**
    * **主題**：對主視窗的 UI 架構進行了一次決定性的重構，以解決頑固的佈局與滾動問題。
    * **最終方案**：廢除 `QTabWidget`，改用 `QMenuBar` + `QStackedWidget` 的導航模式，並為每個功能面板提供獨立的 `QScrollArea`。
